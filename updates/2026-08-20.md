PR #1227 fixes something different and genuinely interesting: **inverted scope precedence** in
`Resolve()`.

```diff
 func scopePrecedence(scope string) int {
   switch scope {
-  case ScopeHub:           return 1
+  case ScopeRuntimeBroker: return 1
-  case ScopeUser:          return 2
+  case ScopeHub:           return 2
   case ScopeProject:       return 3
-  case ScopeRuntimeBroker: return 4
+  case ScopeUser:          return 4
```

A broker-scoped secret was ranked *strongest*, so a stale one could silently shadow a
project- or user-scoped secret that was meant to win. Good catch, and their commit message is
candid about it being backwards relative to every other precedence-ordered resolver in the
codebase.

encouraging that someone is actively working in that exact file.
