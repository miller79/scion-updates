# 2026-08-25 — Rebuilding every image behind a corporate proxy, and a wrong turn on the way

The goal was mundane: get a current `sciontool` into the agent images so the `--scope` flag
works without patching binaries into running containers by hand. Doing it properly meant
rebuilding the images from source. That turned out to be impossible as shipped, produced a
concrete patch we are running now, and surfaced two new findings along the way.

## No image builds at all behind a blocked registry

The first attempt died on the root image:

```
npm error code ECONNRESET
npm error network request to https://registry.npmjs.org/chrome-devtools-mcp failed
```

`core-base` is the base of the entire DAG, so this is not a partial failure — **zero of the
eleven images build**. What makes it a finding rather than a fact of life is that there is no
knob. Six of the eleven images fetch from npm or pip, and every one of them addresses the
public registry directly.

Worth noting what *did* get through in the same build: `deb.debian.org` pulled 72 packages,
`dl.k8s.io`, `go.dev` and `raw.githubusercontent.com` all fine. Only the language package
managers are affected.

Details and the patch are in [issue 9](../FINDINGS.md), which we rewrote today — it had been
filed as a minor `make web` annoyance and it is considerably more than that.

## A wrong turn worth recording

With the mirror configured, six packages still 404'd:

```
@anthropic-ai/claude-code · @openai/codex · @google/gemini-cli · opencode-ai · @playwright/cli
```

Four of the five are AI coding CLIs. We concluded the corporate JFrog Curation policy was
deliberately blocking AI tooling pending approval — which is an entirely plausible thing for
an enterprise to do, fit the evidence, and was **wrong**.

The control that broke it was fetching a package nothing had touched:

```
tiny-invariant   anon=404   auth=200   anon-after=200
```

The mirror returns 404 for anything not already in its cache, and only an *authenticated*
request causes it to fetch from upstream. Every one of those packages was simply cold. Once
authenticated, all six installed — including `@anthropic-ai/claude-code@2.1.235`.

The lesson generalises past our environment: on a caching mirror, "package not found" and
"you are not authenticated" are the same error message. We had assumed a policy decision from
a 404 for about half an hour. If the upstream docs ever cover the mirror case, that failure
mode deserves a sentence.

## The credential cannot be a build-arg

The obvious way to pass mirror credentials is a build-arg. That would be a mistake: build-args
are recoverable from `docker history`, so any published image leaks the token. We used a
BuildKit secret instead —

```dockerfile
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc,required=false npm install -g chrome-devtools-mcp
```

— gated on an optional `NPM_CONFIG_FILE` in the local-docker and local-podman builders, with
`required=false` so unauthenticated builds behave exactly as before. Verified afterwards that
`docker history | grep -c authToken` returns `0` for every image.

Eight images built. `hermes` then failed on the pip half of the same problem, which we have
not fixed.

## Two more findings

`hermes` failing surfaced [issue 27](../FINDINGS.md): `--target` accepts only groups, not
individual images, and the run aborts on first failure. `hermes` sorts before `opencode`, so
one blocked pip install took down two images that had nothing to do with it. Getting the one
image we needed meant hand-writing a `docker build` and reproducing the `BASE_IMAGE` wiring
the orchestrator normally computes.

Then we wanted to hide the harnesses this team does not use, which surfaced
[issue 26](../FINDINGS.md). There is no disable operation. `harness-config delete` exists but
does not stick — the bootstrap re-imports any directory still on disk whose row is missing, so
the config returns on the next restart. This is the same shape as the seeded-policy problem in
issue 16, which `65482def` fixed for policies with tombstones; harness configs did not get
that treatment.

The schema already has `status = pending | active | archived` and the list handler filters to
active by default. Nothing an operator can reach ever sets `archived`. We set it directly in
SQLite and moved the unwanted directories aside. It held across a restart, but that is not an
operation an operator should be performing, and we would not bet on it surviving an upgrade
that re-seeds bundled configs.

## Where the hub ended up

Four harnesses visible (claude, copilot, gemini-cli, opencode), four archived. Agents now run
images built from source at `2b8be982` rather than pulled from an upstream personal registry —
which also closes a supply-chain gap we had flagged earlier but had no practical answer for.
`sciontool` in those images supports `--scope`, so the credential-capture path works without
hand-patching containers.

Two caveats we are not going to paper over: only the `copilot` image has been exercised at
runtime, and agents created before the switch keep running their old images until they are
recreated.
